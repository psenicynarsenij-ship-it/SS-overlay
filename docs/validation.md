# Проверки второго спринта

## Среда и выполненные проверки

Linux Debian 13 x64, .NET SDK 8.0.426 / runtime 8.0.32, Tesseract 5.5.0.
Windows native DLL из NuGet — Tesseract 5.0 (имя tesseract50.dll); эквивалентность
результатов между платформами проверяется Windows-job CI отдельно от Linux.

- Первоначальный полный цикл: сборка без ошибок, 69/69 тестов.
- После выделения конвейера и проверок отмены: 73/73 теста, 0 пропусков.
- Повторная финальная проверка включает locked restore, сборку решения, все тесты,
  консольное демо и self-contained публикацию win-x64.
- В Linux пакет успешно собран и содержит EXE, runtime, обе native DLL, eng.traineddata и demo PNG.
- `dotnet list DotaHpAlert.sln package --vulnerable --include-transitive`: известных уязвимостей не найдено
  по доступному NuGet advisory feed на момент проверки. Это не аудит нативного кода Tesseract/Leptonica.

Автотесты включают пороги, интервалы и повторы, гистерезис, смерть/неизвестный статус,
профиль Invoker, недостоверность, настройки каналов, парсер, все fixtures, полный путь
скриншот → crop → OCR → AlertEngine, независимость от карты, повторное использование/Dispose OCR,
PNG roundtrip, валидацию ROI и параметров, JSON-хранилище, повреждённые настройки,
отмену конвейера, ожидание callback, ошибки захвата и ошибки потребителя.

## Сравнение OCR

Измерено 9 конфигураций: 3 предобработки × 3 режима сегментации Tesseract.
Это сравнение конфигураций **одного OCR-движка**, не сравнение разных производителей OCR.
Windows.Media.Ocr не выбран: требует Windows и установленных OCR language capabilities,
не позволяет провести тот же переносимый эксперимент в Linux. Tesseract использует включённую
лёгкую eng-модель tessdata_fast и постоянный нативный экземпляр.

13 fixtures: 2 реальных скриншота, 7 положительных и 4 отрицательных синтетических crop.
Для каждой конфигурации — прогрев каждого файла и 10 измерений на файл (130 временных замеров).
Отчёт оценивает правильность по последнему результату каждого файла; тесты отдельно проверяют
выбранную конфигурацию на всём наборе. Все исходные результаты и confidence: `ocr-benchmark.json`.

Выбран Otsu + PSM 7: точность на доступном наборе выше остальных при небольшой задержке.
Для 2298 HP и 59 HP confidence 0,91. По отдельности порог BrightText не проходит установленный
порог уверенности для первого реального скриншота; grayscale не распознаёт его. Эти неудачные
варианты не скрыты и не используются как fallback, который мог бы повысить ложные срабатывания.

Время `MedianMs/P95Ms` — предобработка, OCR и парсер готового crop, **без** чтения PNG с диска.
При включении загрузки/декодирования файлов медиана 5,78 мс, p95 47,08 мс.
Создание выбранного экземпляра OCR в эксперименте — около 56,82 мс, отдельно от кадровых замеров.
Прогрев ОС/модели и разрешение изображений влияют на результаты; это не гарантия времени кадра на Windows.
В живом захвате полный screenshot не декодируется: GDI возвращает только ROI 140×25 пикселей.

## Повторное использование и память

`ocr-stress.json`: 50 прогревочных + **5000** последовательных распознаваний low.png,
0 недостоверных результатов; среднее время 7,62 мс на вызов в отдельном stress-прогоне.
GC-измерения исключены из времени OCR. Результат нельзя напрямую сравнивать с медианой другого прогона.

После прогрева приватная память процесса: 103 608 320 байт; после прогона: 121 028 608 байт.
На промежутке 1000–5000 кадров промежуточные замеры оставались 123 912 192 байт.
Живая managed-память после принудительной GC: 108 744 → 127 792 байт (включает список замеров).
Наблюдалось начальное расширение heap/кэшей, линейного роста на этом прогоне не видно.
Это не доказывает отсутствие утечек в Windows GDI/WPF: их проверка требует Windows-сессии.

## Ограничения

- В Linux не запускались WPF, GDI-захват игры, звуковой выход и интерактивный оверлей.
- Успешная self-contained кросс-публикация не подтверждает запуск на Windows.
- Windows CI проверяет сборку, portable tests с native Windows OCR и упаковку;
  визуальные проверки и работа с игрой остаются в `windows-checklist.md`.
- Реальных образцов всего два; требуется больше данных для иных HUD scale, разрешений,
  низкого HP на другой подложке, сглаживания, смерти героя и закрытого интерфейса.
- Автоматическая калибровка ROI, определение героя и признака смерти не реализованы.
- GDI не гарантирует корректный кадр в exclusive fullscreen/защищённых поверхностях.
- Кооперативная отмена ждёт текущий нативный вызов OCR; принудительное прерывание DLL не применяется.
- Выход приложения может быть отключён пользователем в микшере Windows.
