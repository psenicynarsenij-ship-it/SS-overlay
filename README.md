# SS Overlay — Dota HP Alert

Внешний оверлей для Windows 11 x64, C# / .NET 8 / WPF. Читает **абсолютное числовое HP**
из небольшой заданной области интерфейса Dota 2 и передаёт измерения в `AlertEngine`.
Захват выполняется только у видимого активного окна. Чтения памяти игры, управления героем,
инжекции и автоматического определения Invoker нет.

## Запуск на Windows 11

1. Установить .NET 8 SDK x64 и [Microsoft Visual C++ Redistributable 2015–2022 x64](https://aka.ms/vs/17/release/vc_redist.x64.exe).
2. Из корня репозитория:

   ```powershell
   dotnet restore DotaHpAlert.sln --locked-mode
   dotnet test tests/DotaHpAlert.Tests -c Release
   dotnet run --project src/DotaHpAlert.App -c Release
   ```

3. Для первого запуска без игры включить **Профиль Invoker** и нажать **Демо без Dota**.
   Демо циклически подаёт изображения в настоящий OCR, затем в AlertEngine и каналы уведомлений:
   HP 800 → 350 → 349 → 25 → 25 → 25 → 800 с шагом 2 секунды.
   Ожидаются первое предупреждение, повтор и сброс. Профиль по умолчанию выключен.
4. Для проверки скриншотов нажать **OCR изображения…**. Большое изображение обрезается
   по заданной области HP; маленькое считается готовым crop. Показаны исходный crop,
   распознанный текст, HP, уверенность и задержка. В этом режиме звук и оверлей не включаются.
5. Для игры выбрать оконный режим без рамки, указать точный заголовок окна (по умолчанию `Dota 2`)
   и область **только с числом HP**, включить Invoker, нажать **Захват игры**, вернуть игре фокус.
   Сворачивание/потеря фокуса приостанавливают захват с диагностикой и сбрасывают тревогу.

Область по умолчанию: **X=855, Y=1018, W=140, H=25** в физических пикселях клиентской области
для предоставленных скриншотов 1920×1080. Она содержит `текущее / максимальное` HP,
не захватывает карту, регенерацию справа или ману снизу. Другие разрешения, HUD scale,
DPI и расположение интерфейса требуют ручной настройки; автоматической калибровки нет.
Координаты оверлея задаются отдельно в экранных WPF DIP; допускаются отрицательные значения для второго монитора.

Настройки сохраняются кнопкой в `%LOCALAPPDATA%\DotaHpAlert\settings.json` и загружаются при старте.
Запись использует временный файл и замену; повреждённый файл не перезаписывается автоматически.
Настройки захвата/каналов меняются после остановки. Выключение профиля во время работы сразу
скрывает оверлей, запрещает новые уведомления и отменяет фоновую обработку.

**Стоп** и закрытие окна отменяют цикл и ожидают завершения текущего кадра. Нативный OCR
не прерывается посередине вызова; новые кадры после отмены не обрабатываются.

## Сборка Windows x64

```powershell
.\scripts\publish-win-x64.ps1
```

Либо без запуска PowerShell-скрипта:

```powershell
dotnet publish src/DotaHpAlert.App -c Release -r win-x64 --self-contained true -p:RestoreLockedMode=false -o artifacts/win-x64
```

Запускать `artifacts/win-x64/SS-Overlay.exe`. Копировать **всю папку**, включая `x64/`,
`tessdata/` и `demo/`. .NET включён в публикацию; VC++ runtime остаётся системным условием.
Не включены trimming и single-file, чтобы сохранить загрузку нативных DLL и модели.
Публикация занимает около 172 МБ на диске в проверенной среде, основная часть — .NET/WPF runtime.
Это не оценка потребления памяти приложением.

GitHub Actions проверяет Linux и Windows: сборка, тесты с настоящим OCR, консольное демо;
на Windows публикует x64 и сохраняет приложение как артефакт `DotaHpAlert-win-x64`.

Core не зависит от Windows, WPF, OCR и библиотек изображений. Recognition также переносим;
на Linux использует `libtesseract.so.5`, на Windows — x64 DLL из NuGet Tesseract 5.2.0.
Фактическая Windows-библиотека в этом пакете называется `tesseract50.dll`.
Декодирование STB полностью управляемое, без ImageSharp, OpenCV и дополнительного native image runtime.
Языковая модель `tessdata_fast` включена в Git: при запуске сеть не требуется.

Один фоновый потребитель владеет OCR и AlertEngine. Кадры не накапливаются, callback
ожидается до следующего захвата. Экземпляр Tesseract и модель используются повторно.
По умолчанию OpenMP ограничен одним потоком, если `OMP_THREAD_LIMIT` не задан пользователем.
Период захвата — 500 мс (2 кадра/с); разрешён диапазон 100–10000 мс.
На каждом кадре освобождаются временные ресурсы GDI, нативный текст и результаты OCR;
движок освобождается после завершения цикла. Журнал ограничен 100 строками.

Оверлей — прозрачное topmost-окно с `NOACTIVATE`, `TRANSPARENT`, `TOOLWINDOW`,
скрывается через 2 секунды или при сбросе/ошибке захвата. Каждый показ повторно вызывает
`SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE)`; оконные сообщения исключают активацию и перехват мыши.
Скрытие окна из захвата не применяется. Позиция, оказавшаяся вне всех мониторов, переносится
в рабочую область основного экрана с диагностикой.

Звук — собственный короткий `sounds/hp-alert.wav` (450 мс), включённый в публикацию.
NAudio.WinMM воспроизводит его с программным усилением; громкость 0–100% задаётся ползунком,
сохраняется в JSON как `SoundVolume` (0–1, по умолчанию 0,7). Существующие настройки без этого
поля загружаются с громкостью 70%. Одновременно играет не более одного предупреждения:
повтор во время воспроизведения пропускается, после завершения/ошибки можно повторить.
Системные настройки устройства/микшера Windows всё равно влияют на слышимость.

Кнопка **Тест уведомления** показывает HP=123 и запускает WAV независимо от OCR, игры,
профиля Invoker и переключателей звука/оверлея. Она использует выбранную позицию и громкость;
при 0% журнал явно сообщает `SoundMuted`. Если захват запущен, кнопка сначала останавливает
его и дожидается очистки, чтобы кадры игры не сбросили ручное уведомление.

`NotificationRouter` из Core доставляет визуальный и звуковой каналы независимо:
ошибка оверлея не блокирует звук, ошибка звука не останавливает OCR.
В диагностике видны `EngineIssued` (Show/Repeat и флаги каналов), `OverlayRequested`,
`OverlayShown`/`OverlayError`, `SoundRequested`, `SoundStarted`/`SoundError`, завершение,
подавление при остановке и пропуск занятого аудиоканала. `OverlayShown` подтверждает видимость HWND,
а не фактическую видимость поверх игры; `SoundStarted` означает принятие запроса backend,
а не подтверждение слышимости из динамиков.

## Правила уведомлений и достоверности

- Профиль Invoker включается вручную; без него предупреждений нет.
- HP < 350 активирует тревогу; повтор не чаще одного раза в 5 секунд по монотонному `TimeProvider`.
- HP >= 375 сбрасывает состояние; 350–374 сохраняет его, включая повторы уже активной тревоги.
- Недостоверное измерение не активирует и не повторяет тревогу. Уже показанное уведомление
  остаётся до собственного таймера; единичный сбой OCR больше не прячет его сразу.
- Известная смерть сбрасывает тревогу. OCR сам не определяет смерть: `IsAlive = null`.
  Нулевое HP само по себе не превращается в достоверный признак смерти.
- OCR принимает только полную строку `123` или `123 / 456`, с текущим HP <= максимального,
  пределом 100000 и уверенностью >= 0,65. Буквы не исправляются в цифры.
  Whitelist цифр намеренно не используется: посторонний текст должен отклоняться.
- Уверенность — оценка Tesseract, не гарантия. При неверной области или похожем постороннем
  числовом тексте возможны ложные распознавания. Набор из двух реальных скриншотов ограничен.

## Проверки на Linux и CLI

Нужны .NET 8 SDK и нативный Tesseract 5 (`sudo apt-get install libtesseract5` на Debian/Ubuntu).
Все команды — из корня репозитория:

```sh
dotnet restore DotaHpAlert.sln --locked-mode
dotnet build DotaHpAlert.sln -c Release --no-restore
dotnet test tests/DotaHpAlert.Tests -c Release --no-build
dotnet run --project src/DotaHpAlert.Demo -c Release --no-build
dotnet run --project src/DotaHpAlert.Diagnostics -c Release -- 'tests/fixtures/Dota 2 Screenshot 2026.10.24 - 17.55.17.90.png'
dotnet run --project src/DotaHpAlert.Diagnostics -c Release -- --benchmark tests/fixtures/manifest.json docs/ocr-benchmark.json
dotnet run --project src/DotaHpAlert.Diagnostics -c Release -- --stress tests/fixtures/synthetic/low.png 1000
```

Diagnostics коды завершения: 0 — успешно/достоверно, 1 — недостоверный OCR,
2 — ошибка загрузки/настройки. Benchmark записывает все варианты, включая неудачные;
его код 0 означает завершение эксперимента, а не точность всех режимов.

Проверены два пользовательских оригинала: **2298 HP** и **59 HP**. Автотест изменяет пиксели карты
и проверяет неизменность области и результата HP. Дополнительно есть 11 явно синтетических изображений:
7 положительных, пустое поле, шум, текст меню и некорректная дробь.
Синтетические fixtures можно регенерировать через `python scripts/generate-fixtures.py`
(Pillow и DejaVu Sans); пользовательские изображения и записи манифеста сохраняются.

Подробные измерения и ограничения: [docs/validation.md](docs/validation.md).
Практические проверки Windows: [docs/windows-checklist.md](docs/windows-checklist.md).
Сведения о сторонних компонентах: [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).


Проверки доставки уведомлений: [docs/notification-fix.md](docs/notification-fix.md).
Windows-тесты без Dota запускаются отдельно:

```powershell
dotnet test tests/DotaHpAlert.WindowsTests -c Release
```

Они проверяют создание WPF HWND, topmost/click-through/no-activate, положение на мониторе
и декодирование WAV с программной громкостью. Они не проверяют реальную игру или аудиовыход.

## Fluent Dark — рабочая версия SS Overlay (спринт 3)

Самостоятельная Windows x64 сборка: артефакт **SS-Overlay-Fluent-Dark** → распаковать всю папку →
**SS-Overlay.exe**. Это рабочее приложение, отдельное от DesignPreview.
Новый интерфейс, оверлей SUN STRIKE с центральным HP, пресеты позиции, встроенная библиотека из шести звуков,
прослушивание и fallback описаны в [docs/fluent/README.md](docs/fluent/README.md).
После отдельного подтверждения прав все пять переданных MP3 входят в сборку. Импорт удалён.
Подробнее: [библиотека звуков](docs/fluent/sound-library.md).
